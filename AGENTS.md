# Repository Guidelines

## Структура и архитектура

ClipCanvas — локальный видеоредактор для Windows 10/11 x64. Python/FastAPI обслуживает браузерный интерфейс; FFmpeg выполняет монтаж, faster-whisper распознаёт речь, yt-dlp импортирует видео по URL.

- `engine/clipcanvas_server.py` — API, проекты, очередь задач и обработка медиа; `clipcanvas_media.py` — функции шкалы времени и субтитров; `url_import.py` — импорт ссылок.
- `engine/launch.py`, `engine/install.py`, `Start.ps1`, `Stop.ps1` — запуск, зависимости и остановка процессов.
- `web/` — обычные HTML, CSS и JavaScript без отдельной сборки.
- `tests/` — модульные, интеграционные и браузерные проверки; `docs/` — инструкции проверки и удалённого доступа.
- `data/uploads`, `data/jobs`, `data/projects`, `data/models` — пользовательские материалы, результаты, проекты и модели. `.runtime/` содержит зависимости, временные файлы и журналы.

## Запуск и команды разработки

Выполняйте команды из корня проекта. Нужен Python 3.12/3.13 x64; первый запуск подготавливает зависимости в `.runtime/deps`.

```powershell
powershell.exe -NoProfile -ExecutionPolicy Bypass -File .\Start.ps1 -NoBrowser
powershell.exe -NoProfile -ExecutionPolicy Bypass -File .\Stop.ps1
python -B -m unittest discover -s tests -p "test_*.py" -v
python -B tests/integration_smoke.py
python -B tests/launcher_smoke.py
```

Первая команда запускает сервер на `http://127.0.0.1:8787`, вторая останавливает его. Используйте тот же Python, что выбран приложением. Последние команды проверяют модульную логику, настоящий FFmpeg и жизненный цикл запуска соответственно.

## Стиль кода и имена

Используйте четыре пробела в Python; для многострочного JavaScript — два. Сохраняйте стиль окружающего кода, избегайте массового переформатирования компактного `web/app.js`. Python-функции и переменные называйте в `snake_case`, классы — `PascalCase`, JavaScript-функции и DOM-идентификаторы — `camelCase`. Пользовательские сообщения пишите на русском. Настроенных линтеров и форматтеров в поставке нет. Изменяя зависимости, согласуйте `requirements.txt` и `requirements-lock.txt`.

## Проверка изменений

Модульные тесты используют `unittest`: файлы `test_*.py`, методы `test_*`. Добавляйте регрессионные проверки изменённого поведения; числовой порог покрытия не задан. Для монтажа проверяйте таймкоды, звук и короткий экспорт MP4. Браузерные сценарии `ui_*.cjs` требуют Playwright, Chromium и изолированного QA-сервера. ASR-проверка требует локального исходника и модели tiny; сетевые проверки зависят от внешнего источника. Храните тестовые результаты в `.runtime/qa`; подробности — `docs/verification.md`.

## Коммиты и pull request

В текущей папке отсутствует `.git`, поэтому исторические соглашения проверить нельзя. Пишите короткие сообщения, описывающие действие, например `Fix subtitle timing after advert insertion`. В PR укажите проблему, изменения, выполненные проверки и связанную задачу; для интерфейса приложите снимки экрана. Обновляйте `README.txt` и `CHANGELOG.md` при изменении пользовательского поведения.

## Данные и конфигурация

Не включайте пользовательские видео, результаты, кэш и токены в коммиты или архивы. Для изолированных проверок задавайте `CLIPCANVAS_DATA`. Удалённый запуск выполняйте по `docs/remote-access.md`: конкретный VPN-IP и токен обязательны; привязка к `0.0.0.0` запрещена.
