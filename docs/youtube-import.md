# Импорт YouTube

Скачивает **ПК с движком**, даже если ClipCanvas открыт в браузере ноутбука.
Доступ в браузере ноутбука, его VPN и его вход в YouTube не передаются ПК автоматически.

## Обычная загрузка

1. В «Материалы → Видео по ссылке» вставьте ссылку на отдельный ролик.
2. Нажмите «Проверить ссылку», выберите качество и «Скачать в материалы».
3. Не меняйте подключение ПК между проверкой и скачиванием: адреса потоков могут быть привязаны к IP.

## Если YouTube требует вход или подтверждение «не робот»

1. Откройте ролик в браузере, войдите в свой аккаунт и самостоятельно пройдите проверку, если она появилась.
2. Экспортируйте cookies **youtube.com** в текстовый формат **Netscape cookies.txt**. JSON не подходит. Следуйте [инструкции yt-dlp по экспорту cookies YouTube](https://github.com/yt-dlp/yt-dlp/wiki/Extractors#exporting-youtube-cookies). Cookies дают доступ к сессии: не публикуйте их и не отправляйте в чат.
3. В ClipCanvas раскройте «Видео по ссылке → Подключение YouTube», нажмите «Подключить cookies.txt» и выберите файл. Можно сделать это с ноутбука: файл передаётся вашему ПК с движком по тому же подключению, что материалы проекта.
4. Проверьте ссылку заново и запустите скачивание. «Удалить сессию YouTube» удаляет сохранённые cookies из ClipCanvas.

Программа сохраняет только cookies домена YouTube. В Windows сессия зашифрована DPAPI для текущей учётной записи; временная копия для загрузчика удаляется после его вызова. Сессия не входит в проект, API не возвращает её содержимое, cookies и заголовки авторизации исключаются из кэша сведений о видео. Пароль вводится только на сайте YouTube.

Cookies могут истечь или быть отозваны. В этом случае повторите подключение. Они не снимают ограничение запросов по IP: при HTTP 429 подождите и проверьте подключение **ПК**. Успешный вход не гарантирует доступ ко всем роликам. ClipCanvas не проходит CAPTCHA автоматически.

## Диагностика

В папке задания `data/jobs/<id>/` находятся `download.log`, а при обновлении отклонённого потока — `download-refresh.log` и `download-retry.log`. Обновление выполняется один раз; при требовании входа или HTTP 429 повторов нет. Журналы и файлы сессий не добавляйте в Git.
