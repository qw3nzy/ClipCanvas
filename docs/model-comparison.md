# Модель, настройки и локальная проверка

Проверено 5 октября 2026 года. Ранее модель была жёстко задана как
`qwen3.5:4b`, Ollama `http://127.0.0.1:11435`. Она выбирала сцены по диалогам
и шести JPEG-кадрам каждого окна и предлагала исправления субтитров.
Речь распознаёт отдельный faster-whisper; замена LLM не меняет модель ASR.

Теперь модель выбирается в разделе «Настройки». Рекомендуемый более мощный
локальный вариант — `qwen3.5:9b`, Q4_K_M. 4B остаётся вариантом для скорости
и небольшой памяти. Если 9B ещё не установлена, существующая установка 4B
продолжает работать. `Setup-AI.cmd` устанавливает 9B; переменная
`CLIPCANVAS_AI_INSTALL_MODEL=qwen3.5:4b` позволяет установить меньший вариант.

## Оборудование и кандидаты

На проверенном ПК `nvidia-smi` показывает RTX 4060 с 8188 MiB видеопамяти;
Windows сообщает 17 102 110 720 байт RAM, то есть примерно 16 GiB.

| Вариант | Размер установленной модели / требования | Решение |
| --- | --- | --- |
| Qwen3.5 4B Q4_K_M | 3 324 173 934 байта | Сохранена; быстрее, слабее исправляет некоторые русские ошибки |
| Qwen3.5 9B Q4_K_M | 6 550 825 550 байт | Установлена; более мощный локальный вариант, умеренный выигрыш в отдельных проверках языка |
| Gemma 3 12B Q4_K_M | По каталогу 8,1 GB весов, дополнительно нужен контекст | Для 8 GiB GPU запас мал; не скачивалась и не тестировалась |
| Модель через OpenAI-совместимый API | Требования к GPU переносятся на выбранный сервер | Поддерживается как явная настройка; внешнего ключа для реального сравнения не было |

Qwen публикует для 9B против 4B MMMLU 81,2/76,1 и VideoMME с субтитрами
84,5/83,5. Это общие тесты производителя, **не измерение качества русских
субтитров ClipCanvas**. Модель поддерживает текст и изображения.
Источники: [карточка Qwen3.5-9B](https://huggingface.co/Qwen/Qwen3.5-9B),
[пакет Ollama 9B](https://ollama.com/library/qwen3.5:9b),
[Gemma 3 12B](https://ollama.com/library/gemma3:12b).

При локальном анализе платы за запросы нет; остаются затраты на оборудование,
электричество и загрузку весов. 9B загружает больше RAM/VRAM: в проверенном
журнале Ollama 32 из 33 слоёв размещены на GPU, один — на CPU; занято около
7,2 GiB GPU вместе с другими процессами. API оплачивается по тарифу выбранного
провайдера. Стоимость облачного анализа не измерялась, пользовательские кадры
и расшифровки ни одному облачному API не отправлялись.

## Реальные фрагменты и результаты

Использован существующий локальный русскоязычный анимационный эпизод,
длительность 1333,082 с, с сохранённой ASR-расшифровкой проекта. Три разных
отрезка: 15–60, 450–490 и 1240–1285 с. Для каждого модель получила одинаковые
шесть реальных кадров 480 px и одинаковую транскрипцию. Проверялись выбор сцен
и корректура. Температура 0,15, seed 42, контекст 8192, лимит ответа 2400,
рассуждения выключены. Сырые ответы сохранены только в `.runtime/qa`.

| Фрагмент | Наблюдения по 4B | Наблюдения по 9B |
| --- | --- | --- |
| 15–60 с, разговор персонажей | Приняла ошибку ASR про бассейн за шутку; придумала несуществующее слово в заголовке | Не повторила это слово, но также неверно описала разговор; все предложенные границы отклонены валидатором |
| 450–490 с, диалог и действие | Слишком абстрактно описала конкретное действие; исправила «мноя» на «мною», но другие правки сохранили бессмыслицу | Описание конкретнее; исправила «мноя» на «мною» и оставила больше сомнительных фраз без изменений; точный момент действия всё равно требует просмотра |
| 1240–1285 с, завершение сцены и озвучка | Исправила «рек» на «Рек», хотя в словаре указан Рик; ухудшила глагол в другой строке | Исправила имя на «Рик» и сохранила форму глагола; одну сильно повреждённую фразу неверно перефразировала. Порог сходства 0,55 её не отсеял, поэтому просмотр исправлений остаётся обязательным |

Таким образом, более крупная модель полезна для части языковых ошибок и более
сдержанной корректуры, но **локальный прогон не подтвердил безусловное улучшение
поиска сцен**. На плохой ASR-транскрипции обе модели ошибаются. 9B выбирается как
более мощный доступный вариант с сохранением 4B для скорости; автоматическое
применение смысловых предложений не добавлено. Нужны дополнительные примеры
лекций, разговорного видео и чистых русских транскрипций для более общей оценки.

| Задача | 4B, секунды | 9B, секунды |
| --- | ---: | ---: |
| Сцены 15–60, первый запрос с загрузкой | 50,58 | 89,77 |
| Корректура 15–60 | 7,50 | 13,98 |
| Сцены 450–490 | 7,38 | 9,22 |
| Корректура 450–490 | 2,61 | 2,61 |
| Сцены 1240–1285 | 5,05 | 11,77 |
| Корректура 1240–1285 | 2,83 | 4,33 |

Время включает серверный вызов и проверку доступности, но не извлечение кадров
и распознавание речи; измерено по одному запуску, без статистической оценки.
Холодный запуск зависит от RAM, дискового кэша и уже работающих приложений.
Нельзя переносить эти цифры на полный фильм как гарантированную скорость.

Локальные артефакты: `.runtime/qa/model-comparison/results.json`,
`.runtime/qa/run_model_comparison.py`. Файл `model-reference.srt` содержит
извлечённую встроенную русскую дорожку для дополнительной проверки смысла;
это другой перевод, поэтому посимвольная метрика относительно него не считалась.
Эти файлы содержат пользовательский материал и не должны входить в архив поставки.

## Настройки и ключи

Серверный файл `.runtime/ai-config.json` хранит провайдера, имя модели, адрес,
поддержку изображений, разрешение внешней передачи, контекст, лимит ответа,
тайм-аут и режим структурированного JSON. На Windows API-ключ шифруется DPAPI
текущего пользователя. GET настроек и состояние модели показывают только
`api_key_configured`; ключ не попадает в проекты, задания, URL, аргументы
процесса или браузерное хранилище. При смене адреса сохранённый ключ сбрасывается.
Пустое поле ключа сохраняет его, отдельное действие удаления очищает его.
Администратор также может задать ключ переменной `CLIPCANVAS_AI_API_KEY`;
переменная имеет приоритет, и для удаления такого ключа надо очистить окружение
серверного процесса.

Для OpenAI-совместимого сервера нужны базовый адрес обычно с `/v1`, имя модели
из `/models`, поддержка `/chat/completions` и JSON Schema либо JSON mode.
Изображения передаются как `image_url` с JPEG data URL. Для текстовой модели
отключите изображения: корректура и интро/аутро используют текст, поиск сцен
переключается на диалоги. Внешний адрес должен использовать HTTPS; передача
диалогов и кадров разрешается отдельной настройкой. Прокси окружения и HTTP
перенаправления отключены, чтобы избежать непреднамеренной передачи ключей.

Кнопка проверки соединения проверяет доступ и наличие выбранной модели через
список моделей; она не выполняет платную генерацию и не гарантирует поддержку
всех функций конкретного API. Ошибки авторизации, неизвестной модели, квоты,
тайм-аута и неподдерживаемого формата выводятся по-русски без тела ответа
провайдера. Кэш анализа учитывает провайдера, адрес, имя, параметры и digest
локальных весов. Для изолированного сервера/тестов используется
`CLIPCANVAS_AI_CONFIG_FILE`.

## Интро и аутро

Анализ использует имеющиеся реплики и выборочные кадры, отдельно рассматривает начало и конец
видео. На каждый край — один компактный запрос; это оставляет место в контексте
для JSON-ответа. Первый вариант с двумя краями в одном запросе на реальном
материале превысил 8192 токена и был исправлен до приёмки.

Предложение содержит исходные секунды, объяснение на русском, субъективную
уверенность и реплики-доказательства. Границы выбираются из существующих
таймкодов реплик. Сервер отклоняет выход за край окна,
нечисловую уверенность, выдуманные ID и разрезание реплики. Кнопка «Найти и удалить»
применяет предложения с оценкой от 0,9; обычный поиск оставляет ручное принятие.
Визуальные границы рассчитывает код по сменам сцен: внутри интервала нужны минимум
два подтверждающих кадра и отсутствие кадров основного материала. Край окна
выборки не считается доказательством границы заставки. Отдельная классификация отличает обращение автора,
титры, сюжет и неопределённость: последние две категории не допускаются к удалению.
Обычные приветствия персонажей и сцена после титров не должны считаться заставками.
Отсутствие предложений допустимо.

Положительный контрольный текст (явно синтетический урок автора, не реальное
видео из сравнительной таблицы) дал ожидаемые предложения 0–6 с и 92–98 с
на 9B; обработка двух краёв на загруженной модели заняла 7,58 с. Исправлена
обнаруженная путаница ID: модель выбирает первую и последнюю реплики включительно,
а их фактические времена берёт сервер; ID не трактуются как секунды.
Артефакт проверки: `.runtime/qa/model-comparison/positive-boundaries.json`.

В финальном повторе на реальном эпизоде 9B вернула пустой список (79,75 с
с загрузкой модели). 4B предложила только короткую фразу с указанием озвучки
1261,54–1264,02 с (55,09 с с загрузкой), не затрагивая последующий сюжет после
титров. Тип обращения в объяснении 4B неточен: это кредит озвучки, а не прощание
автора. Оба результата требуют обычного просмотра. Сюжетный разговор в начале
не предложен к удалению. Артефакт: `.runtime/qa/model-comparison/boundaries-verified.json`.

Немые заставки, музыка, OCR титров и аудио-классификация пока не анализируются:
без текста здесь возвращается пустой список. Семантическая ошибка модели всё
равно возможна; временная валидация проверяет границы, а не художественный смысл.

## Проверки интеграции

`tests/test_ai_config.py` проверяет DPAPI/write-only ключ, смену endpoint,
HTTPS/opt-in, отсутствие утечки секретов в ошибках и кэше, преобразование кадров,
отсутствующую модель, настоящий HTTP-вызов к локальному OpenAI-совместимому
имитатору, остановку дочернего процесса и очистку временных файлов. Для
интро/аутро проверены исходные ID, отдельные окна, уверенность, доказательства,
запрет разрезания реплик и неизменность исходной расшифровки.

Настоящий внешний API не проверен: пользовательский ключ не был предоставлен.
Совместимость произвольных провайдеров не гарантируется; проверена описанная
форма API и локальный Ollama 0.35.1.
